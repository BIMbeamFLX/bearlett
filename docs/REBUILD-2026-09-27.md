# Bearlett rebuilt from LUD-25

27 September 2026, branch `feat/rebuild`. Felix decided that day to rebuild
Bearlett from dni's spec instead of porting it ("wir bauen bearlett jetzt
sauber neu auf von dni specs die sind könig"), to drop the old tests, and to
write the new test suite once the build is finished.

## Decisions

| Question | Decision |
| --- | --- |
| Protocol code | Written from the spec text; `@lnurlcash/kit` is only a comparison oracle in tests. This reverses the 20 September rule "bump the kit, never edit protocol code". |
| Where it runs | One code base: the web app and the docked Hangar napplet. Only network, storage and keys are wired per platform. |
| Cashu, NutFT, LNURLvault hardware | Not part of the new Bearlett. Felix is the only holder of 600B Cashu cards, so the TCG is rebuilt on LNURLcash without a card migration (a later phase). |
| Notes from the old Bearlett | A one-time, removable import path (`src/wallet/legacy.ts`). Felix expects no funds there. |
| Tests | The old suites are dropped. The new suite comes after the build. |

## The committed test suite

Written after the build, as decided: 401 tests (`npm test`) and a CI job
that has the kernel judge Bearlett's spends.

| Part | What it holds Bearlett to |
| --- | --- |
| `tests/spec` (219) | LUD-25's test vectors 1-5; the conformance suite's `spends.json` (bearer notes, key path over five domains and their cross checks, a three-leaf tree with a real internal key, BIP-342 signatures in a leaf, the 17 time-claim rules, the leaf policy, malformed `cw1`, invalid `cp1`, short forms) and `part2.json` (eight reference branches, the pre-purpose derivation the import reads, certificates, address proofs, encodings) |
| `tests/lnurl` (154) | `bech32`, `bolt11`, `url-admission`, `input-resolution`, `note-url`, `pay-request` (with invoices and LUD-21 verify), `withdraw-info`, `fees` (including an exact gross-up) |
| `tests/wallet` (28) | Every flow over real HTTP against the conformance mock mint, including an answer lost after the burn landed, a mint that drops answers and refuses replays, an answer that confirms nothing, a crash between sending and recording, a melt that fails or never settles, a lying mint, a changed mint key, a rate limit, offline receipt, the sealed vault, and the import against the real kit 0.19.5 |
| `tests/kernel` (CI) | lnurlcash-kernel 0.1.0 judges the 14 spends of `cases.ts`; every verdict must equal Bearlett's |

What the vectors and flows turned up, and was fixed: the branch is derived
from the mint's host with its port while spends bind the hostname (as the
reference wallet does; mints are keyed by host now); a non-zero locktime is
judged against the clock even under a final sequence; an open burn looks `p1`
up before it is sent again (a crash could otherwise roll back a burn that
landed); the background settle skips what is being sent; a spec-breaking
answer (`ProtocolError`) is no longer taken for a missing one; a received
note its sender spent first is marked spent and logged; plus the wire details
in the LNURL commit (`e088e88`).

Feedback for lnurlcash-conformance, not yet sent: `signature.json` still
certifies `hex(sha256(k1))` with hex signatures, which the unified model
replaced by `cs1` over `hex(Q)`; and `withdraw-info.json` refuses an answer
without `mintPubkey` as mandatory, while `50d740a` makes certifying a SHOULD
and the suite's own grader only warns. Bearlett follows the spec on both.

## Not checked yet

- A real lnurl-mint (`272d948`) with a Lightning backend: this machine has no
  Docker. Timelock spends after T are judged by the kernel, not yet by a mint.
- The napplet inside the Hangar (not pinned yet).

## Known limits

- Registering a Lightning Address needs the web app; the Hangar's
  NAP-RESOURCE only GETs.
- A locked note is not found by a scan from the words alone: its locktime is
  in the wallet's records, not the seed.
- A bearer note handed out is a random preimage. If the device is lost
  before the recipient rotates it, taking it back is no longer possible (the
  recipient still holds it).
- No offline app shell (PWA) and no NAP-INTENT handling yet.
- Seals and the TCG on LNURLcash are the next phase.
